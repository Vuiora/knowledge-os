# 需求文档

## 简介

本文档定义了工程师知识系统的需求规范 - 这是一个综合性的个人知识管理平台，集成了多种工具（Obsidian、Wiki.js、MkDocs），基于统一的 Git 知识仓库和 AI 驱动的知识助手。该系统使工程师能够通过五层层次结构（基础、技术、架构、项目、洞察）来捕获、组织、连接和检索技术知识。

## 术语表

- **知识系统（Knowledge_System）**: 用于管理工程知识的完整集成平台
- **知识仓库（Knowledge_Repository）**: 基于 Git 的中央存储，包含所有 Markdown 格式的知识内容
- **知识层（Knowledge_Layer）**: 组织知识的五个层次类别之一（基础、技术、架构、项目、洞察）
- **Obsidian_Vault**: 用于创建概念间双向链接的个人知识图谱界面
- **Wiki_服务（Wiki_Service）**: 用于团队协作和文档管理的 Wiki.js 实例
- **文档站点（Documentation_Site）**: 由 MkDocs 生成的公开技术文档静态网站
- **AI_助手（AI_Assistant）**: 基于 RAG 的语义搜索和知识检索系统
- **向量数据库（Vector_Database）**: 用于语义搜索的嵌入向量存储
- **知识图谱（Knowledge_Graph）**: 通过双向链接创建的互联概念网络

## 需求

### 需求 1: Git 知识仓库结构

**用户故事:** 作为一名工程师，我希望有一个具有清晰层次结构的统一 Git 仓库，以便我能够系统地组织所有知识并对学习进度进行版本控制。

#### 验收标准

1. 知识系统 应当 创建根目录为 `knowledge-system/` 的仓库结构
2. 知识仓库 应当 包含子目录：`knowledge/`、`wiki/`、`site/` 和 `obsidian/`
3. `knowledge/` 目录 应当 实现五个层次结构：`01-foundations/`、`02-technologies/`、`03-architecture/`、`04-projects/` 和 `05-insights/`
4. 当 仓库初始化时，知识系统 应当 自动创建所有必需的目录结构
5. 知识仓库 应当 对所有知识文档使用 Markdown 格式

### 需求 2: 五层知识层次结构

**用户故事:** 作为一名工程师，我希望将知识组织成从基础概念到个人洞察的五个不同层次，以便我能够系统地从理论导航到实践。

#### 验收标准

1. `01-foundations/` 层 应当 包含子目录：`operating-system/`、`network/`、`algorithm/` 和 `database/`
2. `02-technologies/` 层 应当 包含子目录：`embedded/`、`ai/` 和 `cloud/`，其中 `embedded/` 包括 `mcu/`、`rtos/`、`driver/` 和 `protocol/`
3. `03-architecture/` 层 应当 包含子目录：`embedded-system/`、`distributed-system/` 和 `platform/`
4. `04-projects/` 层 应当 支持项目特定的子目录，示例包括：`smart-ring/` 和 `anti-snore-pillow/`
5. `05-insights/` 层 应当 包含子目录：`engineering/`、`career/` 和 `technology-trend/`
6. 当 用户添加内容时，知识系统 应当 允许根据内容类型放置在任何适当的层次中

### 需求 3: Obsidian 集成

**用户故事:** 作为一名工程师，我希望使用 Obsidian 在概念之间创建双向链接，以便我能够构建一个揭示不同主题之间联系的个人知识图谱。

#### 验收标准

1. Obsidian_Vault 应当 直接指向 `knowledge/` 目录
2. 当 用户使用 `[[链接]]` 语法创建 Markdown 文件时，Obsidian_Vault 应当 自动创建双向链接
3. Obsidian_Vault 应当 生成显示所有互联概念的可视化知识图谱
4. 当 用户打开 vault 时，Obsidian_Vault 应当 将所有五个知识层显示为可导航的文件夹
5. Obsidian_Vault 应当 支持图谱视图以可视化知识连接

### 需求 4: Wiki.js 团队知识库

**用户故事:** 作为团队成员，我希望有一个与 Git 仓库同步的协作 wiki，以便我的团队能够访问和贡献共享知识文档。

#### 验收标准

1. Wiki_服务 应当 自动从 Git 仓库同步内容
2. Wiki_服务 应当 支持 Git 存储后端配置
3. `wiki/` 目录 应当 包含面向团队的内容，包括：`company/`、`architecture/`、`product/` 和 `development/` 子目录
4. 当 Git 中的内容更新时，Wiki_服务 应当 在可配置的同步间隔内反映更改
5. Wiki_服务 应当 提供基于 Web 的编辑功能以支持团队协作

### 需求 5: MkDocs 文档站点

**用户故事:** 作为一名工程师，我希望将技术文档发布为静态网站，以便我能够公开或在组织内分享知识。

#### 验收标准

1. 文档站点 应当 从 `site/docs/` 中的 Markdown 源文件生成静态 HTML
2. `site/docs/` 目录 应当 包含子目录：`embedded/`、`architecture/` 和 `ai/`
3. 当 执行 `mkdocs serve` 时，文档站点 应当 提供本地预览服务器
4. 当 执行 `mkdocs build` 时，文档站点 应当 生成可部署的静态文件
5. 文档站点 应当 使用 `mkdocs.yml` 中的配置来设置站点结构和主题

### 需求 6: 基于 RAG 的 AI 知识助手

**用户故事:** 作为一名工程师，我希望有一个能够基于我的知识仓库搜索和回答问题的 AI 助手，以便我能够快速检索相关信息而无需手动搜索。

#### 验收标准

1. AI_助手 应当 实现检索增强生成（RAG）架构
2. 当 知识仓库更新时，AI_助手 应当 为新文档或修改的文档生成嵌入向量
3. 向量数据库 应当 存储文档嵌入向量以支持语义搜索
4. 当 用户提出问题时，AI_助手 应当 从向量数据库检索相关文档并生成上下文相关的答案
5. AI_助手 应当 在其回答中引用知识仓库中的源文档
6. AI_助手 应当 支持关于技术主题的查询，例如"STM32 DMA 原理"、"FreeRTOS 调度"和"BLE 协议"

### 需求 7: 日常知识工作流

**用户故事:** 作为一名工程师，我希望有一个简化的工作流来捕获日常学习，以便我能够持续构建知识库而不会有摩擦。

#### 验收标准

1. 当 用户学习新信息时，知识系统 应当 支持在 Obsidian 中在适当的知识层内创建新的 Markdown 文件
2. 知识系统 应当 支持在内容创建期间添加双向链接
3. 当 内容达到成熟度时，知识系统 应当 允许选择性地发布到 Wiki_服务或文档站点
4. 知识系统 应当 为所有知识更改维护 Git 版本历史
5. 知识系统 应当 支持每日增量添加，而无需批量操作

### 需求 8: 系统集成与同步

**用户故事:** 作为一名工程师，我希望所有工具都使用相同的 Git 仓库，以便我对所有知识有一个单一的真实来源。

#### 验收标准

1. 知识系统 应当 使用 Git 作为所有组件的中央数据源
2. 当 通过任何界面（Obsidian、Wiki.js 或直接 Git）修改内容时，知识系统 应当 在所有工具之间保持一致性
3. 知识系统 应当 支持 Git 和 Wiki_服务之间的自动同步
4. 知识系统 应当 在仓库更改时支持 AI_助手的自动嵌入更新
5. 知识系统 应当 通过适当的 Git 工作流实践防止冲突

### 需求 9: 可扩展性和长期增长

**用户故事:** 作为一名计划积累 10 年以上知识的工程师，我希望系统能够高效处理数千个文档和连接，以便随着知识库的增长性能保持可接受。

#### 验收标准

1. 知识系统 应当 支持存储至少 5,000 个 Markdown 文档而不会出现性能下降
2. 知识图谱 应当 高效渲染具有 10,000+ 双向链接的图谱
3. 向量数据库 应当 支持跨数千个嵌入文档的高效语义搜索
4. 文档站点 应当 能够成功构建数千页的内容
5. 知识系统 应当 通过适当的实践（例如，如果需要，使用 Git LFS 处理大文件）保持 Git 仓库性能

### 需求 10: 部署和基础设施

**用户故事:** 作为一名工程师，我希望使用 Docker 在单个服务器上部署整个系统，以便我能够以最小的基础设施复杂性运行所有组件。

#### 验收标准

1. 知识系统 应当 为所有服务提供 Docker Compose 配置
2. 知识系统 应当 包含以下容器：Wiki_服务、向量数据库和 AI_助手
3. 当 启动 Docker Compose 时，知识系统 应当 使用适当的网络和卷挂载初始化所有服务
4. 知识系统 应当 使用 Docker 卷在容器重启时持久化数据
5. 知识系统 应当 暴露适当的端口以便 Web 访问 Wiki_服务和文档站点
6. 知识系统 应当 支持基于环境的配置以实现部署灵活性
